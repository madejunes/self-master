# Curriculum Architecture

## Status

Planning only. The curriculum is intentionally not locked.

## Design Principle

The curriculum should approximate the intellectual breadth and depth of a
strong master's-level software engineering education while allowing a
project-driven, self-directed structure.

ACM/IEEE-CS GSwE2009 explicitly emphasizes integrating theory and practice,
mastering a common body of knowledge, professional practice, flexibility,
and continual curriculum revision. Carnegie Mellon SEI's historical model
also included software systems engineering, specification, design,
generation/maintenance, verification/validation, and project management.

Primary references:
- ACM/IEEE-CS, Graduate Software Engineering 2009 (GSwE2009)
- Carnegie Mellon Software Engineering Institute graduate curriculum materials
- Relevant current standards, books, papers, and authoritative technical sources

## Mastery Levels

The eventual model should distinguish at least:

### Level 1 — Familiarity
Can explain core ideas and terminology accurately.

### Level 2 — Competence
Can apply concepts to well-defined engineering problems.

### Level 3 — Advanced
Can handle ambiguity, compare alternatives, reason about trade-offs,
and diagnose difficult problems.

### Level 4 — Master's-level
Can integrate theory and practice, critically evaluate evidence,
handle open-ended problems, read research literature, formulate
defensible positions, conduct investigations, and communicate
independent conclusions.

The exact rubric will be designed in PLAN mode before coursework begins.

## Curriculum Flexibility

Not every topic deserves equal time.

For each topic we should ask:

1. Is it foundational?
2. Is it important to the user's target competence?
3. Is it needed to understand later material?
4. Is it current/relevant?
5. Can the user already demonstrate competence?
6. Can it be learned efficiently when needed?

Topics may be:
- Core
- Supporting
- Elective
- Just-in-time
- Skip/defer

## Intended Progression

Foundation
→ advanced engineering
→ quality/reliability
→ AI engineering
→ integrated intelligent systems
→ research method
→ independent research/capstone

This is a direction, not a fixed semester schedule.
